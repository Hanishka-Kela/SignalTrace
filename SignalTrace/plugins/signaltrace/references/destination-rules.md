# Citation and source decision rules

Read this reference for destination tracing or external source verification.

For each observed citation preserve: nearby claim text, anchor text, authored URL, redirect hops, final URL, response state, and the entity/task the final representation actually supports. A canonical difference is not a variant failure unless resolved evidence conflicts. A documented rename or successor is not broken. Assign responsibility as `site-published link`, `external publisher`, `assistant-generated citation`, or `unresolved`; never assign an invented URL to the audited site.

Only call a destination wrong when the cached final page positively supports a different entity, version, variant, region, configuration, or task. Missing context is ambiguous. A homepage destination is a finding only when an attached specific claim cannot be supported there and a site-published citation caused the loss.

External verification is targeted: fetch only input-supplied evidence sources. Compare the same entity and predicate with all scope qualifiers intact. Independence requires distinct origin and no observed canonical/feed-copy relationship. Two copies support only two-source agreement, not web-wide agreement. Restricted, placeholder, locked, or image-only evidence cannot corroborate a claim. No suitable source means `not assessed`.

For `Organization` and `Person` JSON-LD, treat each external `sameAs` URL as a site-published identity claim. The entrypoint may resolve that exact URL through the shared governor and inspect only public identity evidence such as the title, `og:title`, `og:site_name`, primary heading, profile metadata, or identity JSON-LD. Do not authenticate, call platform APIs, or parse social feeds. Compare names through `scope.py`; a platform-decorated title may be a plausible match when it contains the declared name. If the declared node has no `name`, do not substitute page text: comparisons are `insufficient-evidence` and the aggregate verdict is `not assessed`. The aggregate uses a deterministic conservative rule: a compatible or declared-name substring match is `plausible match`; otherwise any `conflicting` result is `conflicting`; insufficient evidence is `not assessed`. A positive different identity, confirmed dead HTTP destination, or explicit parked/for-sale page is a High identity-destination finding under the shared severity table. Timeout, network failure, missing comparable identity text, and robots denial are coverage states.

Negative controls: no `sameAs` property is `not applicable`; robots denial is `not assessed`; a destination that explicitly documents a rename or successor is not broken merely because the URL changed; and one legitimate identity URL resolving to the named local business produces zero findings. A redirect is an observation until the final cached page positively establishes a different identity or another confirmed destination defect.
